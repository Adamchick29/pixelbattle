# Проверка реализации — 27 октября 2026

## Приложение

- API: **24 теста прошли** на настоящих PostgreSQL 18 и Redis 8. Проверены регистрация, нормализация email, пароль, сессия и выход, Origin, лимиты, границы поля, 20 одновременных запросов одного аккаунта, задержка, повторный цвет, конфликт участников и учет просмотров.
- Фронтенд: **4 теста прошли** — декодирование поля, последовательность событий, обнаружение пропуска, повторные события и идентификаторы загрузок на HTTP.
- Браузер: **10 сценариев прошли** в Chromium desktop и Pixel 7. Два теста пропущены намеренно для неподходящей платформы: touch на desktop и повторная проверка VMUI на mobile.
- Проверены регистрация и покраска из интерфейса, получение события вторым браузером, задержка после перезагрузки, выход, восстановление изменений после offline, перемещение, зум двумя пальцами и отсутствие горизонтального переполнения.
- Production-сборка, TypeScript и ESLint проходят. При установке зафиксированных npm-зависимостей найдено **0 уязвимостей**.

## Хранение и контейнеры

- `alembic upgrade head` применен к чистой базе; `alembic check` не обнаружил расхождений с моделями.
- Финальные Docker-образы собраны; все девять работающих сервисов запущены. Задача миграции завершается с кодом 0.
- Поле, версия, аккаунт, время следующей покраски и действующая сессия сохранились после перезапуска PostgreSQL, Redis, API и фронтенда.
- В финальном образе фронтенда доступны лицензии Pixelkit и Pixelify Sans.

## Мониторинг

- Без пароля VMUI отвечает 401; с паролем открывает интерфейс и четыре проектных дашборда.
- Каждый MetricsQL-запрос дашбордов выполнен через маршруты, используемые VMUI, без ошибок.
- VictoriaMetrics получает данные API, node_exporter и cAdvisor; HTTP-пробы проходят.
- Протестировано изменение readiness и метрики Redis при отказе зависимости.

## Деплой

- Workflow проверен actionlint, shell-скрипты — ShellCheck.
- Проверены валидация конфигурации, экранирование bcrypt-хеша, защита от изменения паролей существующей базы и остановка при некорректном вводе до выполнения команд.
- На изолированной Ubuntu 24.04 с SSH проверены установка Docker/Compose из официального apt-репозитория, передача релиза, миграции, запуск сервисов, VMUI и метрики.
- Повторный SSH-деплой успешен, существующий аккаунт сохранен.
- Намеренно неуспешная миграция записала новую версию схемы и завершилась с кодом 23. Автоматический откат вернул предыдущий API/фронтенд/proxy без запуска старого Alembic; приложение и вход в сохраненный аккаунт продолжили работать.
- Linux-скрипт локальной настройки создал `.env` с правами 0600, отказался перезаписывать его и прошел этап настройки пароля из CI.

В тесте Ubuntu использовался вложенный Docker: запуск systemd-сервисов заменен тестовым адаптером, запускающим настоящие containerd и dockerd. Вместо публикации и скачивания собственных образов GHCR использовались предварительно загруженные локальные образы. Работа контейнеров, база, миграции, SSH, HTTP и экспортеры выполнялись реально. Тестовый VPS, временный SSH-ключ, сеть и образы тестового окружения удалены.

Публикация в GitHub/GHCR и запуск на пользовательском VPS требуют адреса репозитория и настроенных GitHub Secrets/Variables из README. Эти внешние учетные данные не были предоставлены, поэтому внешний production-деплой не выполнялся.
